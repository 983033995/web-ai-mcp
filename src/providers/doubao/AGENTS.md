# Doubao 验证约束

- 请求启用了 `support_chunk_delta` 时，验收必须包含真实或合成 `CHUNK_DELTA`，不能只用 `OK` 短回复覆盖 SSE。
- `710022004` 是 HTTP 响应要求验证，不证明原网页已经显示验证码。没有实际显示证据时，不要让用户去网页盲找挑战。
- 风控命中规则不在响应中时明确保留未知；网页正常、刷新参数后成功或等待后成功都不能单独确定根因。
- 生成必须以 `2074/creation_block` 的实际媒体状态和结果地址为依据；文字承诺不证明已排队或完成。视频可能经后续独立消息送达；使用只读历史查询，不通过重发生成或聊天询问轮询。IM JSON 请求保留观察到的 `Content-Type: application/json; encoding=utf-8`。
- 用户指定视频默认 `Seedance 2.0 Fast`（网站值 `seedance_v2.0`）。模型映射必须来自网页配置，不凭名称推测 ID；Fast/2.0/Mini 为 4–15 秒，2.5 为 4–30 秒。每次调用显式选择或使用默认，不静默继承或降级模型。
- 图片比例、风格和视频时长同时进入 ability 参数与可见生成指令；仅参数传输成功不能证明输出遵循规格。参考图使用 `resource_type=2`，必须验证同一 URI 的提交与图片元数据，不能当 TXT 附件或复用浏览器已上传图片冒充 Node 上传成功。
- 一旦客户端收到验证码要求，阻断后续网站写入；不要通过新会话、自动重试或换账号继续探测。
- 真实专家思考包含 `10040/thinking_block` 容器及 `10000/text_block` 子块，按 `parent_id` 分离思考和答案；仅合成 `10040/text_block` 测试不能证明真实思考协议兼容。文件流的 `DOWNSTREAM_VERBOSE_INFO` 和删除占位块补丁也必须有真实结构依据与回归后才能宣称接入。
