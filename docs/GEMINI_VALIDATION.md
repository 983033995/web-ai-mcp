# Gemini 网页聊天、媒体与多账号验证

## 当前状态（2026-10-22）

用户明确要求运行时不依赖固定浏览器或打开的网页。已撤回浏览器聊天实验，所有 Gemini 工具恢复 HTTP；固定 `browserChatSpaceId` 不再是有效配置。该次浏览器错误已确认发生在已不存在的任务空间15，尚未进入 Google 登录校验。

独立 HTTP 只读检查另返回 `authentication_error`；对同一账号的一次正常登录 Cookie 续期返回 HTTP 401，因此停止网站请求，没有提交聊天、切号或重放。移除浏览器依赖已经完成代码与本机配置修改，但这不代表认证或 HTTP 聊天当前可用。需在本机更新一次本人的登录凭据，再独立验收模型查询和聊天。下方原生浏览器成功记录仅为已撤回通道的历史证据。

## 历史验证

日期：2026-10-20。Gemini 为当前源码中的实验性 provider，尚未包含在已发布的 `web-ai-mcp@0.4.0` 中。仅连接本人获准使用的 `gemini.google.com` 账号，不是官方 Gemini API 或 OpenAI 兼容代理。

2026-10-21 复核：更新本机凭据后，实际 stdio MCP 模型读取通过；Argon/High 文字请求仍在约一分钟返回网站错误记录，没有完整答案或候选。相同本人账号的官网 Argon/High 对话能返回答案，不能据此宣称 HTTP MCP 聊天已恢复。本次同账号凭据重读、身份核对及响应 Cookie 更新修复不保证解决该流错误；没有自动换账号、重放失败请求或把网页答案冒充 MCP 结果。旧的成功记录仅描述当时兼容性。

后续定位：当前网页在请求中带有与正文绑定的原生完整性校验，而已有 HTTP 请求仅复制登录状态。没有复制、伪造或重放该校验；新增显式 `browserChatSpaceId` 聊天通道，由正常网页界面完成原生提交，仍通过 MCP 返回结果。实际 stdio MCP 的 Argon/High 已返回完整摄影精修方案（约千字、完整 c/r/rc），首轮约121秒。后续新 MCP 进程使用相同本地 key 续聊，c 不变且 r/rc 推进，但该轮模型给出拒答，不能称为上下文语义验收通过。HTTP 路径本身仍未恢复，也没有自动回退或重放旧请求。

同一会话的 TXT 上传随后通过实际 stdio MCP 验收：新进程上传已授权目录内的非敏感说明文件，Argon/High 正确返回文件中指定的项目代号、唯一口令和六个字段；原本地 key 和网站 c 保持不变，r/rc 推进，约122秒。这证明原生文件提交、异步结果读取和跨进程续聊链路可用；此前纯文字拒答仍如实保留。文件准备阶段暴露了网页截断文件名和隐藏进度元素的差异，已改为确认附件数、可见上传状态与原生发送就绪；准备失败时没有发送正文或重放网站消息。

最终构建再启动独立 MCP 进程，不上传新文件、沿用相同 key，并省略模型/等级参数；约132秒返回上一份附件的项目代号，并正确解释其中两个字段。原账号与网站 c 未变，r/rc 推进，保存的 `4 Argon` / `high` 保持不变，跨进程上下文验收通过。当前配置仅为默认账号显式启用原生聊天；其他账号仍按原配置，媒体能力未在本轮重新生成验收。本机290项测试、typecheck/build和隔离 npm package smoke 通过。

另确认一类网站错误会以完整候选正文 `Sorry, something went wrong. Please try your request again.` 返回，原来被误标为成功。现在文本流和文本历史均将该完整失败提示返回为错误并保留不确定会话保护；引用该句的正常回答不受影响。确定性测试覆盖错误识别、浏览器进程输出、账号/草稿/繁忙页面保护、严格历史候选选择及私有上传副本清理。

## 实现范围

- `gemini_chat`：网站默认模型、普通文字聊天、命名/默认会话、`session_key` / `conversation_id`、后台任务和正常重启续聊。`system_prompt` 仅作为文字前缀。
- `gemini_sessions_list` / `gemini_session_close`：只读列出或忘记本地映射，不删除网站历史。
- 每轮先读取网站登录上下文，确认邮箱与请求 token 后才提交一条消息；账号哈希不匹配时拒绝旧会话。仅持久化会话、回复、候选标识和账号哈希。
- 只有配置本人 Cookie 和正常 User-Agent 时才注册 Gemini。Gemini-only 启动不需要 DeepSeek token 或 PoW WASM，工具发现不访问网站。

首阶段仅验证默认模型聊天；图片、视频、多账号和高级输入的扩展范围见下文。网站搜索控制、Deep Research、Gems 和隐藏思考文本仍未启用；没有 `gemini_reasoner`。网页菜单中的项目需要协议与实际 HTTP 交叉验证，不能单凭菜单宣布支持。

## 证据与边界

### 接入前的 HTTP 验证

本人账号的三次独立 Node 进程验证了 `StreamGenerate` 路径：首轮完整回复约 14.5 秒、续聊约 8.5 秒、关闭浏览器后再次启动进程续聊约 5.2 秒。三轮网站会话标识一致，回复及候选标识推进；后两轮仅发送会话信息和本轮问题，没有重传前文。

浏览器使用的较新 `processSession` 通道只在独立 Node 探测中完成握手、消息提交和控制帧接收，未确认完整答案；未重放该消息或继续使用那条不确定会话。本实现不使用该通道，也不自动回退浏览器。

测试全部使用合成 HTML、Cookie、会话标识和响应，不含真实账号、网站回复或导入的第三方源码。

### 本人账号实际 MCP

使用 `scripts/probe-gemini.ts --env-file /private/path/.env --live` 验证实际构建后的 stdio 入口。该脚本显式授权三条普通故事消息，覆盖后台首轮、同会话回忆、MCP 进程重启后的回忆；不向网站发送测试、MCP 或技术标记，不自动重发。

本人账号实际构建后的 MCP stdio 已完成三轮验收：后台首轮成功；第二轮准确回忆要求的颜色与地点；关闭客户端并启动新的 MCP 进程后，第三轮正确回忆人物、物品、颜色和地点。三轮网站会话一致，回复及候选标识各自推进；会话文件不含消息、Cookie、请求 token 或邮箱。浏览器在这组三轮开始前已关闭。只测试网站默认模型，没有推断具体模型名称。

接入过程中，另有四条消息暴露了客户端解析器的兼容差异：实际长度为 UTF-16 JSON 长度加两侧换行，终止帧后有 `e` 统计帧，`af.httprm` 数字会随轮次变化且其时间值不必与 `di` 相等。全部捕获响应经离线解析确认完整；没有重发这些消息或恢复不确定映射，而是通过本地关闭工具明确结束对应映射，网站历史不变。只采用合成的同结构 fixture 做回归，原始响应不提交。

最终验收的第二条提问只询问颜色和地点，最初脚本却额外断言物品名称，导致脚本报 `context_not_preserved`；实际回复正确回答了两个被问到的要点。没有重发首轮或第二轮，而是修正后续可复用脚本的提问，并在新进程的第三轮显式询问人物、物品、颜色和地点，验收通过。这是验收断言修正，不是会话恢复或网站请求重试。

首阶段本机 `npm run typecheck`、`npm run build`、`npm test`（192 项）、三种 provider 的 `npm run smoke:local`、Gemini-only MCP Inspector 和三者组合的 21 工具发现、`npm run smoke:package` 均通过。当前媒体扩展新增 5 个工具，Gemini-only 为 12 个、三者组合为 26 个；扩展后的检查结果以本次 PR 为准。

`hNvQHb` 历史 RPC 的生成媒体字段和 `aPya6c` 的只读配额查询均已在本人网页账号观察。配额查询在未耗尽时返回未阻断且无恢复时间；真实耗尽后的未来重置时间路径和 1037 触发由 fixture 验证，不能宣称本人账号已实测撞限额自动切换。无可靠恢复时间时采用用户显式配置的 `cooldownMinutes`，并标记 `configured_backoff`，不冒充网站真实恢复时间。

当前视频的首次异步回包修正已通过确定性测试，尚未因登录失效之后重新提交真实视频验证；已有真实视频生成、历史查询和下载证据如上。未知网站限制和后续协议变化仍可能导致失败，结果不确定时保持阻断。

## 错误与数据处理

- 不重试网站聊天写入。失败可能推进网站状态时标记 uncertain；未知、关闭、被中断或不确定的本地 key 不会悄悄变成新会话。
- 缺少完整回复标识时，仅返回有用文字和不可续聊警告，不返回可用 key。流截断或错误帧不能当作完整答案。
- 验证码使该客户端停止后续网站调用，直至用户通过官网处理并显式更新配置/重启；不伪造身份、解挑战或切换账号。
- Cookie、请求 token、邮箱、原始响应与消息不写入产品会话存储或 Git。网站验证输出仅为脱敏步骤摘要。临时凭据在验收结束后清除。
- 不强制过期本人凭据或刻意触发网站验证码/限流。相关故障由确定性 fixture 验证；匿名只读页面对照验证了缺少账号字段和请求 token，不发送匿名消息。

## 运行与许可限制

实测环境为 macOS、Node 26.7.0，使用本机已有代理。Node `fetch` 不自动使用系统代理；需要代理时建议 Node 24+，显式设置 `NODE_USE_ENV_PROXY=1` 和 `HTTPS_PROXY`。不修改系统设置或关闭 TLS 校验。CI 的 Node 20/22/24 仅使用本地 fixture，不能证明这些版本上的实时账号兼容性。

## 模型、思考等级与附件扩展（2026-10-20）

新增只读 `gemini_models`，Gemini-only 共13工具，三者组合共27工具。查询使用 `otAQ7b []`，由当前登录账号提供模型 ID、名称、编号及套餐能力。实测列出 `3.5 Flash-Lite`、`3.8 Flash`、`3.1 Pro`、`4 Argon`；这些名称不硬编码为所有账号通用列表。账号已通过初始化登录校验时，RPC 状态字段 `null` 与 `1000` 都是有效状态。未观察过的容量字段13仍不可选择。

网页有 Low / Medium / High 三档。偏好写入 `L5adhe [0][264]` 与当前生成 protobuf 字段81共同确认对应 `1 / 4 / 2`；旧 `StreamGenerate` 使用 JSPB slot80，并与模型 header 对齐。没有把 Medium 合并成布尔 extended thinking，也不改账号偏好来完成每轮选择。浏览器当前使用 `processSession` 传输；产品仍使用单独验证的 `StreamGenerate`，不依赖浏览器代发。

图片原生比例菜单只有 `1:1`、`3:4`、`4:3`、`16:9`、`9:16`，生成请求的 packed 字段56.1分别为 `61 / 60 / 62 / 63 / 59`。视频菜单为 Landscape / Portrait，消息字段10.7.1.4分别为 `1 / 2`。网页构造的对照请求在发出生成正文前被取消，仅用于确定字段；不是完成生成的证据。图片工具编号14、视频编号11。产品设置这些原生字段并保留自然提示词，不用提示词代替控件；不提供任意像素分辨率，下载预览也可能缩放/取整。实际 HTTP 新字段的验收结果与未验证组合需分别对待。

上传使用明确授权目录下的小型非敏感 TXT、JPEG、MP4。`content-push.googleapis.com/upload` 实际返回64字符的 `/contrib_service/ttl_1d/<opaque-id>`，与上传器校验一致；请求没有 Gemini Cookie。上传标识、文件名和内容仅用于本轮内存，私有会话文件检查不含这些数据或 Cookie。代码支持 TXT、PNG/JPEG/WebP、MP4，实际附件组合并非所有格式/模型的穷举验证。MP4分析通过与视频参考生成通过是两件事；后者目前仍为实验参数，可能失败或只返回文字，任何异常都不自动重放。
