# 长聊天等待与使用指引验证

2026-10-19，针对本人 Qoder 真实会话暴露的会话参数误用、约60秒调用失败和失效 key 重试进行优化。原会话、长问题、Cookie 与账号回复没有提交仓库，也没有重放其问题。

## 改动

- MCP 初始化 instructions、`webai_usage` 及每个聊天工具的参数描述提供一致使用规则；可将 `CLIENT_USAGE_SKILL.md` 放到客户端 skill 目录。
- 四个聊天/reasoner 工具支持 `background=true` 和 UUID `request_id`。快速返回 job ID，结果查询不会重发网站写入；相同工具/参数/ID 在当前进程内只执行一次。
- `webai_job_status` 只读返回 running/completed/failed/cancelled 和完成结果；显式 cancel 将 AbortSignal 传至原有 provider，不能撤回网站消息。
- 会话失效和未知 ID 仍失败，不自动创建替代会话。聊天错误附带 `automatic_retry=false` 与分类恢复步骤，未知错误码不回显。
- 同步聊天在客户端提供 progressToken 时每10秒发等待通知；不声称通知一定能延长客户端上限。

## 实际验证

`npm run smoke:long-task` 使用本地 HTTP fixture，经产品 Doubao Provider 与真实 MCP stdio 跑完整流程。网站模拟等待65秒，客户端每次 MCP 调用限时3秒；后台提交约18毫秒返回，重复提交相同 ID 返回同一 job，后续状态查询成功得到答案。网站写入计数为1，完成约70秒，会话为 active。会话文件不含问题、结果或 Cookie。此测试不调用真实网站，不证明当前账号额度可用。

本机只读检查 Qoder 桌面1.1.69的已安装代码发现调用桥使用 `controlRequestTimeoutMs` 的60秒常量；另一层 MCP 服务配置读取 `timeout`。没有改动 Qoder 程序或其依赖。即使服务 timeout 增大，外层上限仍可能存在，因此长聊天使用后台提交/查询。

新增回归覆盖：任务单次执行、重复 ID 防重、ID 与工具/参数冲突、未知/过期任务不重放、取消/截止、异常脱敏、跨会话 key 续聊、参数冲突不发送网站请求、正常同步工具兼容。打包冒烟也从隔离安装包运行短时后台 fixture。

## 边界

后台任务与正文只在内存保留，不写入磁盘，不跨 MCP 重启恢复。最多32个结果、完成后30分钟有效；一次只运行一个后台任务。请求 ID 的摘要记录最多1024个，在当前进程保留以防过期任务重放，达到上限会拒绝新提交。网站超时仍有效，作业额外有12分钟取消截止。读取结果前不要重连/重启；进程中断留下的 pending 会话继续阻止写入。

额度不足目前可能以正常网站回复正文出现；使用指引要求停止，不把提示视为答案，不自动切换模式或 provider。没有根据任意正文关键词强制判错，以免把正常讨论额度的回答误报。首次 Missing Web session ID 的原始响应缺失，未猜测新响应字段或把它归因于问题长度。
